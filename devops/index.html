# 웹·SEO 작성 규칙
- title은 검색어를 앞에, 브랜드는 뒤에 둔다
- 수치는 정합기준 정본만 인용하고 출처를 병기한다
- og:image는 절대 URL로 쓴다
정리 전에 먼저 시켜볼 프롬프트
이 프로젝트에서 지금 적용되는 CLAUDE.md와 지침 파일을 읽어줘. 아직 수정하지 마.

각 규칙을 셋으로 나눠줘.
1) 모든 작업에 필요한 공통 규칙
2) 특정 폴더나 특정 작업에만 필요한 규칙
3) 중복되었거나 지금은 지키지 않는 규칙

그다음 공통 규칙은 짧게 남기고, 나머지는 어디로 옮기면 좋을지 제안해줘.
파일을 바꾸기 전에 변경안과 이유를 먼저 보여줘.
세 문장 넘게 이어지는 절차 설명이 있으면 빼냅니다. 별도 문서나 스킬로 옮기고 자리엔 포인터 한 줄만 남깁니다 — 예: 배포 전 체크리스트: docs/deploy.md 참고 (배포 시작할 때만 읽는다). CLAUDE.md는 목차 역할만 합니다.

@로 파일을 import하는 방식은 텍스트를 그대로 붙여넣기 때문에 권장하지 않습니다. 줄인 의미가 없어집니다.

# AGENTS.md — 시놀 저장소

## 이 저장소에 대해
시놀·시럽 서비스의 문서·프로토타입·어드민 기획 저장소.
프로덕션 코드는 별도 저장소이며 여기서 배포하지 않는다.

## 하지 말 것
- API 키·관리자 비밀번호·회원 데이터를 파일에 기록하지 않는다
- 수치를 임의로 만들지 않는다. 정합기준 정본에 없으면 빈칸으로 둔다
- 기존 색인 URL(칼럼 등)의 경로를 바꾸지 않는다

## 명령
- 문서 빌드: node build.js
- 미리보기: soffice --headless --convert-to pdf

## 출력 규칙
- 빌드 로그는 성공/실패와 오류 3줄까지만 보고한다
- 파일 전체를 붙여넣지 말고 변경한 부분만 보여준다
Codex에서 토큰이 빨리 닳는 가장 흔한 이유는 배경 설명을 프롬프트에 매번 길게 붙이는 것입니다. 반복되는 배경은 프롬프트가 아니라 AGENTS.md에 한 번만 적고, 프롬프트에는 이번에 할 일만 씁니다.
두 파일이 갈라지지 않게 — 공통 규칙(보안·수치·금지어)은 한쪽을 정본으로 정하고 다른 쪽은 포인터로 둡니다. 같은 규칙을 양쪽에 복사해 두면 한쪽만 고쳐지고 두 도구가 다르게 동작합니다. 이 저장소는 CLAUDE.md를 정본으로 하고 AGENTS.md에는 "공통 규칙은 CLAUDE.md 참조" 한 줄을 두는 방식을 권합니다.

    완료 기준 — 루트 CLAUDE.md 200줄 이하, 절차 설명 0건
  2. 2

    규칙 분리

    .claude/rules/와 하위 폴더 CLAUDE.md로 옮깁니다. 문서 작성 규칙은 docs/, 웹·SEO 규칙은 경로 지정으로.

    완료 기준 — 새 세션 /context에서 규칙 항목이 줄어듦
  3. 3

    AGENTS.md 신설

    Codex용 골격을 만들고, 공통 규칙은 CLAUDE.md를 가리키게 합니다. 출력 규칙(로그 3줄, 변경분만)을 반드시 포함합니다.

    완료 기준 — Codex /status·/debug-config(또는 codex doctor)로 로드 확인
  4. 4

    조사 위임 에이전트 정의

    .claude/agents/researcher.md에 "경로와 결론만 반환" 규칙을 넣어 둡니다. 저장소 탐색·로그 분석은 전부 이쪽으로 보냅니다.

    완료 기준 — 조사 작업 후 메인 세션에 파일 본문이 안 남음
  5. 5

    훅·세션 기록 점검

    settings.json의 hooks 설정을 보고 안 쓰는 것을 정리합니다. ~/.claude/projects는 백업 후에만 삭제합니다.

    완료 기준 — 매번 도는 불필요한 훅 0건
  6. 6

    점검 주기 걸기

    /schedule 또는 로컬 cron으로 CLAUDE.md 점검을 주기화합니다. 결과는 PR로만 받고 병합은 사람이 합니다.

    완료 기준 — 점검 주기 1개 이상 등록
자동 병합은 하지 않습니다. CLAUDE.md 변경은 PR로 올리고 사람이 검토·병합하는 것을 시놀 팀 운영 원칙으로 둡니다. 자동 편집 차단 자체는 권한·설정으로 제어합니다.
PART 7 · 측정

바꿨으면 재야 합니다

"느려진 것 같다"를 확인 가능한 문제로 바꾸는 순서 — 진단 → 한 가지 변경 → 같은 작업으로 재확인 → 유지 또는 되돌림.

지표보는 법목표
세션 시작 컨텍스트새 세션에서 /context규칙·문서 항목이 이전보다 감소
압축까지 걸리는 시간같은 작업을 돌려 자동 압축 발생 시점 비교같은 작업에서 압축 횟수 감소
재질문 빈도이미 정한 규칙을 다시 묻는 횟수0에 가깝게
작업당 왕복같은 산출물을 만드는 데 든 턴 수감소
기준선을 먼저 기록하십시오. 바꾸기 전 숫자가 없으면 좋아졌는지 알 수 없습니다. 팀에서 같은 작업 하나를 정해(예: 문서 1종 빌드 + QA) 변경 전후로 같은 방식으로 재는 것을 권합니다.

  • /context로 무엇이 자리를 먹는지 먼저 확인했다
  • 진단 프롬프트를 돌려 원인을 좁힌 뒤에 설정을 건드렸다
  • 주제가 바뀌면 /clear, 이어가면 /compact로 구분했다
  • 루트 CLAUDE.md가 200줄을 넘지 않는다
  • 특정 폴더·작업에만 필요한 규칙은 .claude/rules/나 하위 CLAUDE.md로 옮겼다
  • Codex용 AGENTS.md를 두고 공통 규칙은 한쪽만 정본으로 뒀다
  • 큰 읽기는 Subagent로 위임하고 결론만 받는다
  • 변경은 한 번에 하나씩 하고 같은 작업으로 다시 확인했다
  • 점검 주기를 걸어 두고 결과는 PR로만 받는다
