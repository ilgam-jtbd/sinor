# sinor — 시놀 제품 개발 분석·기획 저장소

> **이 저장소에서는 실 개발을 하지 않습니다.** 시놀(주) 전 서비스(시놀·시럽·시럽인연·시놀트립 등)의
> 진단·기획·설계 산출물과, 기획 → 디자인(UX/UI) → 개발이 **같은 형식으로** 일하기 위한 규격을 관리합니다.

## 여기서 해결하려는 문제

기획이 내린 판단을 디자이너와 개발자가 **다시 해석하는 비용**이 일정의 대부분을 먹습니다.
그래서 내용이 아니라 **형식**을 고정했습니다 — 무엇을 왜 만드는지(One-pager), 어떻게 생겼는지(디자인 핸드오프), 어떤 순서로 짜는지(티켓·에이전트 프롬프트).

## 문서 파이프라인

```
① 진단(실측) → ② One-pager → ③ 목업 → ④ 디자인 → ⑤ 티켓 → ⑥ 에이전트 프롬프트 → ⑦ 검증 → ⑧ 이터레이션
```

**②를 건너뛰고 ⑤로 가지 않습니다.** 개발은 되는데 왜 만들었는지 아무도 모르는 상태가 됩니다.
**가드레일 지표가 빈 One-pager는 반려합니다.** 성공지표만 있으면 "발견은 늘었는데 경험은 나빠진" 상태를 성공으로 읽습니다.

## 원칙

- **읽기 전용 조사** — 프로덕션 변경·계정 생성·개인정보 조회 금지
- **근거 기반** — 확정 항목마다 근거(파일 경로·명령어·응답 헤더·캡처) 명시
- **신뢰도 4단계** — `확정 / 유력 / 추정 / 미확인`. 미확인은 "확인 방법"을 함께 적습니다
- **측정을 미루지 않는다** — 이벤트 부착은 같은 작업에 포함합니다
- **수치는 정본에서만** — `docs/03` 에 없는 숫자는 만들지 않습니다

## 세션 간 역할

| 주체 | 담당 | 하지 않는 것 |
|---|---|---|
| Cowork(시놀) | 전략 판단 · 문서 최종본 · 이해관계자 커뮤니케이션 | 코드 작성 |
| Claude Code | 기술 조사 · 구현 · QA · 배포 | 전략 판단 · 우선순위 변경 |
| 전략기획 세션 | 진단 · 지표 설계 · 기획서·목업 초안 | 최종 승인 |
| 디자이너(UX/UI) | 목업 → 화면 · 컴포넌트 정의 | 기획 합의 없는 구조 변경 |

세 세션의 커뮤니케이션 스레드: **[WHO-224](https://linear.app/whocareskorea/issue/WHO-224/sinor싱크-cowork시놀-claude-code-전략기획-커뮤니케이션-스레드)** (임시 — `Sinor` 팀 신설 시 이관).
판단이 바뀌거나 막히면 그 티켓에 남기고 넘깁니다. 산출물 자체는 이 저장소에서 교환합니다 (`docs/04` 참조).
