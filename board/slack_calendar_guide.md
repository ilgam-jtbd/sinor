# 슬랙 연동 · 구글 캘린더 공유 가이드

시놀 운영보드를 **현재 운영 방식(슬랙 제보 → 에이전트 즉시 작업)** 위에 얹는 방법입니다.
지금 돌아가는 흐름을 바꾸지 않고, 기록과 일정만 한곳에 모으는 것이 목적입니다.

---

## 1. 지금 상황

QA·개선 요청이 **슬랙으로 들어오고 에이전트가 바로 작업**하고 있습니다. 속도는 빠르지만 두 가지가 남습니다.

- **기록이 흩어집니다** — 무엇이 언제 왜 바뀌었는지 나중에 추적이 어렵습니다
- **중복이 보이지 않습니다** — 같은 제보가 여러 번 들어와도 알기 어렵습니다 (실제로 백로그 8쌍 16건이 중복 등록된 사례)

운영보드는 **속도를 늦추지 않고 기록만 남기는 뒷단**으로 씁니다.

---

## 2. 슬랙 유입을 별도로 관리하는 방법

### 2-1. 제목 접두어 규칙

이슈 제목 앞에 유입 경로를 답니다. 검색·필터가 바로 됩니다.

| 접두어 | 의미 |
|---|---|
| `[슬랙]` | 슬랙 채널로 들어온 제보 |
| `[백오피스]` | 운영보드에서 직접 등록 |
| `[CS]` | 고객 문의에서 올라온 건 |
| `[에이전트]` | 에이전트가 자동 등록·처리한 건 |

`Ctrl+K` 전역 검색에서 `[슬랙]`만 쳐도 슬랙 유입 건이 모두 나옵니다.

### 2-2. 등록 템플릿 3종 만들기

이슈 등록 화면 상단 **📋 템플릿 → 현재 폼을 템플릿으로** 버튼으로 아래 3개를 미리 만들어 두면, 다음부터는 선택만 하면 됩니다.

| 템플릿 | 기본값 |
|---|---|
| **[슬랙] QA 제보** | 유형 Bug · 환경 운영 · 검증자 운영·QA |
| **[슬랙] 개선 요청** | 유형 Task · 결함유형 기능개선 |
| **[에이전트] 처리 완료** | 유형 Task · 상태 완료 · 처리 내용만 기록 |

### 2-3. 운영 순서 (권장)

```
슬랙 제보  →  에이전트 즉시 작업 (지금 그대로)
                    ↓
            처리 후 운영보드에 1건 등록
            [슬랙] 접두어 + 처리 내용 + 관련 프로젝트 연결
                    ↓
            주간 브리핑에서 자동 집계
```

핵심은 **먼저 고치고 나중에 기록**입니다. 등록을 먼저 하게 하면 속도가 죽고, 사람들은 다시 슬랙으로만 갑니다.

### 2-4. 중복 방지

등록 전 `Ctrl+K`로 제목 키워드를 검색합니다. 같은 건이 있으면 새로 만들지 말고 기존 이슈에 코멘트를 답니다.

## 3. 구글 캘린더 공유

운영보드의 일정을 경영진·실무자가 각자 캘린더에서 보게 하는 방법입니다.

### 3-1. 공유 대상과 범위

| 대상 | 보는 것 | 캘린더 |
|---|---|---|
| CEO · COO | 마일스톤·배포일·의사결정 기한 | **시놀 경영 일정** |
| PO · 디자인 · 개발 · QA · 시럽 매니저 | 단계별 시작·종료, 담당 배정 | **시놀 개발 일정** |
| 전원 | 릴리즈·점검 공지 | **시놀 릴리즈** |

캘린더를 3개로 나누는 이유는, 하나에 모으면 경영진 화면이 실무 일정으로 가려지기 때문입니다. 각자 필요한 것만 구독합니다.

### 3-2. 연결 방법 (3가지 중 선택)

**① CSV 내보내기 → 캘린더 가져오기 (가장 간단, 지금 바로 가능)**
운영보드 스케줄 화면 우측 상단 **CSV** 버튼 → 구글 캘린더 → 설정 → 가져오기.
수동이라 주 1회 정도가 적당합니다.

**② 구글 캘린더 API 연동 (권장, 개발 필요)**
프로젝트의 `phases`(기획·디자인·프론트·백엔드·QA) 시작·종료일을 캘린더 이벤트로 자동 생성합니다.
- 배포일(`deployDate`)은 **종일 일정**으로
- 담당자(`assignments`)를 **참석자**로 자동 추가
- 일정 변경 시 캘린더도 함께 갱신

**③ 에이전트 자동 동기화 (지금 방식의 확장)**
슬랙 에이전트가 이미 돌고 있으니, 같은 에이전트가 운영보드 → 캘린더로 **단방향 반영**하게 합니다.
양방향으로 두면 두 곳 상태가 갈라지므로, **운영보드를 원본**으로 고정합니다.

### 3-3. 권한

- 경영 일정: CEO·COO **수정 권한**, 실무자 **보기 전용**
- 개발 일정: PO(최지영)·개발(우종선) **수정 권한**, 경영진 **보기 전용**
- 릴리즈: 관리자만 수정, 전원 보기

---

## 4. 하지 않을 것

- 회원 개인정보(이름·연락처)를 이슈나 일정에 적지 않습니다 — 회원 ID·화면 경로만
- 서버 비밀번호·API 시크릿을 어떤 필드에도 넣지 않습니다
- 슬랙을 접수처에서 없애지 않습니다 — 지금 방식이 가장 빠르고, 운영보드는 기록용 뒷단입니다
- 캘린더 양방향 동기화를 하지 않습니다 — 운영보드가 원본

---

## 5. 먼저 정할 것

| 항목 | 정할 내용 |
|---|---|
| 캘린더 연동 방식 | ① CSV 수동 / ② API 연동 / ③ 에이전트 동기화 |
| 캘린더 분리 | 3개(경영·개발·릴리즈) 유지 여부 |
| 기록 시점 | 처리 후 기록(권장) vs 접수 시 기록 |
| 에이전트 자동 등록 | 슬랙 제보를 에이전트가 자동 등록하게 할지 |
