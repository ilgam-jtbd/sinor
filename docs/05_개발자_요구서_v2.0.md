## 1. 실측 — 이 개편의 근거

### 1-1. 지표 계층으로 본 문제

```
매출     = 결제고객 × 객단가
결제고객 = MAU × 결제전환율
MAU      = f(신규유입, 재방문, 부활)
웹 기여  = 앱 설치 + 웹 완결 전환
```

## 4. 컴포넌트·세션 규격 — 이 문서의 핵심

### 4-1. 원칙

> **개발 배포 없이 바꿀 수 있는 범위가 곧 그로스 실험의 속도입니다.**

운영 중 변경 요구는 반드시 발생합니다. 그때마다 개발 배포가 필요하면 개선 주기가 스프린트 단위로 늘어나고, 실험이 사실상 불가능해집니다. **아래 8종은 전부 어드민에서 수정 가능해야 하며, 이것이 이번 개편의 완료 조건입니다.**

또한 **에이전트·개발자가 요구사항을 임의로 확장하거나 변경하지 않습니다.** 더 나은 방법이 보이면 실행하지 말고 티켓에 제안으로 남깁니다. 이 규칙이 없으면 릴리스마다 기획과 구현이 어긋납니다.

### 4-2. 어드민 관리 대상 8종

|---|---|---|---|---|

### 4-3. 콘텐츠·이미지 관리 규격

| 홈 섹션 임프레션 | **세션당 1회**만 집계 (50% 이상 노출 기준) | 스크롤 왕복으로 부풀려지면 기여도 판정이 왜곡됩니다 |
| 수익 카드 | 카드별 **세션당 노출 상한** 설정 가능 | 과다 노출 시 광고로 인지 |
| 채팅 안 읽음 점 | **대화방 실제 열람 시점**에 해제 (탭 진입 아님) | 탭만 눌러도 사라지면 알림 신뢰도가 무너집니다 |
| 탭 스크롤 위치 | 탭별 **독립 보존** | |
| 빈 상태 | 항상 **다음 행동 버튼** 포함 | 빈 화면에서 나가면 그 세션은 아무것도 남기지 못합니다 |

### 4-5. 성능 제약

- 홈 섹션이 9개로 늘어나므로 **초기 로딩 API 호출이 섹션 수만큼 증가하지 않도록** 합니다 — 단일 홈 응답 API로 묶거나, 상단 3개 섹션 우선 렌더링 후 지연 로딩
- 페이지 로딩 시간은 **가드레일 지표**입니다. 배너·스크립트 추가로 인한 지연은 시니어 회선 환경에서 치명적입니다

### 5-3. 그로스 판정 설계

**4주차 — 섹션 기여도 판정**
```
섹션 기여도 = (섹션 탭 수 / 섹션 노출 수) × (해당 경로 전환 수 / 섹션 탭 수)
```
기여도 **하위 2개 섹션은 접거나 순서를 내립니다.** 처음부터 완성형으로 두지 않습니다.

**8주차 — 성공지표·가드레일 판정**

| 지표 | 현재 | 목표 |
|---|---|---|
| DAU/MAU | 5.8% | 8% 이상 |
| 앱 설치 유도 도달률 | 1.4% | 5% 이상 |
| 앱 내 검색 이용률 | 0 | 홈 방문자 대비 15% 이상 |
| 결제 이벤트 기록률 | 20건/7개월 | 실제 결제 대비 90% 이상 |

**가드레일 — 하나라도 악화되면 성공지표가 좋아져도 실패로 판정합니다.**

| 지표 | 판정 |
|---|---|
| 시럽인연 상담 신청 수 | 감소 시 실패 |
| 단체미팅 신청 완료율 | 감소 시 실패 |
| 모임 참여 후 이탈률 | 악화 시 실패 |
| 앱 실행 후 첫 액션까지 시간 | 증가 시 실패 |
| 페이지 로딩 시간 | 증가 시 경고 |
| CS 문의 | 「못 찾겠다」·「설치 창이 계속 뜬다」 별도 태깅 |

### 5-4. A/B 체계

| 대상 | 방식 |
|---|---|
| 홈 검색바 | 앱 버전 분기 50:50, 2주 (양군 각 2,000세션) |
| 섹션 순서 · 수익 카드 문구 | **어드민 변경이므로 서버 사이드 분기 가능** |
| 스마트 배너 vs 하단 바 | 4주씩 교차 운영 |
| 칼럼 하단 카드 목적지 | 주제별 매핑 A/B |

**A/B가 불가능한 경우** — 왜 불가능한지와 대체 판정 방법을 티켓에 적습니다. 배포 전후 비교로 대체할 때는 그 기간 **광고 집행을 고정**합니다.
