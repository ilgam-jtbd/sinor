## 푸는 문제

**회원이 이미 하고 있는 검색에 진입점이 없습니다.** 28일간 4,232명이 5,683회 검색했는데(GA4 2026.07.09~08.05) 앱 홈 최상단에 검색창이 없습니다. 모임은 1,561개 운영 중입니다 — 재고는 충분한데 매대가 비어 있습니다.

## Four Customer Questions

**1. 즉시적인 고객은 누구인가?**
앱을 열었지만 무엇을 볼지 정하지 못한 5060 회원. 이미 검색 의사가 있는 4,232명이 1차 대상입니다. 구매자와 사용자가 같습니다.

**2. Customer Job은 무엇인가?**
"내가 갈 만한 모임을 찾아내는 것." 검색 기능을 쓰고 싶은 게 아니라, **오늘 참여할 곳을 고르고 싶은 것**입니다. 그래서 성공은 검색 실행 횟수가 아니라 **모임 상세 도달**입니다.

**3. 10배 더 잘해야 하는 것은 무엇인가?**
**찾는 시간.** 현재는 카테고리·목록을 훑어 내려가야 하고, 지역이나 취미로 좁힐 방법이 없습니다. 경쟁 앱(오이·문토·캠핏) 대비 우위는 기능이 아니라 **재고 1,561개**입니다. 그 재고에 닿는 시간을 줄이는 것이 유일한 10배 지점입니다.

**4. 성공지표와 가드레일은?**
아래 두 섹션.

## 지표 계층

```
매출        = 결제고객 × 객단가
결제고객    = MAU × 결제전환율
MAU         = f(신규유입, 재방문, 부활)
```

월 신규 회원이 5,964명(2025.02) → 1,361명(2026.07)으로 줄었습니다. **신규로 MAU를 지키는 경로는 이미 닫혔습니다.** 남은 레버는 재방문입니다.

- **내가 올리려는 레버**: 재방문 (DAU/MAU)
- **왜 이 레버인가**: 검색은 **의도가 확인된 행동**입니다. 4,232명이 이미 하고 있는데 진입점이 없다는 것은, 전환율이 높을 곳에 비중이 0으로 눌려 있는 상태입니다. PO 판단 기준 3번(전환율 높은데 비중 낮은 곳 먼저)에 정확히 해당합니다
- **현재값 5.8% → 목표값 8% 이상** (판정 시점: 배포 후 8주)
- 보조 지표: 앱 내 검색 이용률 — 진입점 없음 → **홈 방문자 대비 15% 이상**

## 가드레일

| 지표 | 판정 기준 |
|---|---|
| 앱 실행 후 첫 액션까지 시간 | **증가 시 실패.** 검색창이 선택지를 늘려 오히려 망설이게 만든 신호. 섹션 축소를 검토합니다 |
| 모임 참여 후 이탈률 | **악화 시 실패.** 검색으로 빈 모임·부실 모임에 더 잘 닿게 된 신호 |
| CS 문의 | '화면이 바뀌어 못 찾겠다' 유형을 별도 태깅. 배포 후 2주 집계 |

**세 지표가 모두 미측정 상태입니다.** 측정 설정이 배포보다 먼저입니다.

## MVP 범위

**반드시 포함 (critical path)**
- 홈 최상단 sticky 검색바 — 스크롤해도 따라옵니다 (시니어는 상단 복귀 조작 부담이 큼)
- 플레이스홀더 "어떤 모임을 찾으세요?" 고정 노출
- 검색 화면: 최근 검색어 5건 + 인기 검색어 8건
- **GA4 `view_search_results` + `search_term` 수집** — 화면과 같은 릴리스
- **검색 결과 0건 검색어 별도 로그** — 존재하지 않는 모임에 대한 수요 신호
- 노출·탭·전환 이벤트 부착

**이번에 제외**
- 자동완성·오타 교정
- 필터(지역·요일·연령) — 검색어 로그로 실제 수요를 확인한 뒤 설계합니다
- 검색 결과 정렬 옵션
- 통합검색(모임 외 칼럼·상품) — 1탭 목표가 흐려집니다

**제외 이유**: 최초 가설의 90% 이상은 틀립니다. 무엇으로 좁히고 싶은지를 **검색어 로그가 알려준 다음** 필터를 만듭니다. 순서를 뒤집으면 아무도 안 쓰는 필터가 남습니다.

## 검증 방법

**A/B 테스트: 가능.** 홈 진입 시 검색바 노출군 vs 미노출군 50:50, 2주.
- 1차 지표: 홈 → 모임상세 탭 전환율
- 2차 지표: 7일 재방문율
- 최소 표본: 홈 방문 기준 양군 각 2,000세션 (DAU 2,130 기준 약 2주)

**불가능한 경우의 대체 판정**: 앱 버전 분기 A/B가 불가능하면 배포 전 4주 / 배포 후 4주 비교. 다만 계절성과 마케팅 변동이 섞이므로, 그 기간 광고 집행을 고정하고 판정합니다.

## 선행 조건 — 이것 없이는 착수하지 않습니다

| # | 조건 | 담당 | 상태 |
|---|---|---|---|
| 1 | GA4 `search_term` 수집 설정 | 데이터 | 수집 여부 미확인 |
| 2 | 섹션별 노출·탭 이벤트 체계 | 데이터 | 미설정 |
| 3 | 가드레일 3종 측정 가능 상태 | 데이터 | 전부 미측정 |
| 4 | 앱 홈 AS-IS 화면 캡처 | 운영 | **미확보** |
| 5 | 모임 카테고리 목록·개수 확정 | 기획·운영 | 미확정 (6개 이하면 격자 대신 가로 스크롤 1줄) |
| 6 | 앱 내 검색 구현 방식 — DB LIKE인지 검색엔진인지 | 개발(CC 조사) | 미확인 |

**4번이 특히 중요합니다.** AS-IS 없이 확정하면 개발 중에 "원래 있던 기능이 빠졌다"는 문제가 반드시 나옵니다.
