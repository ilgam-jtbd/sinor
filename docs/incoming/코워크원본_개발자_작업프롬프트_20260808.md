# 시놀 개편 — 개발자 작업 프롬프트 (예시)

> **예시 문서입니다.** 시놀 4대 메뉴 개편을 Claude Code·Codex로 진행하기 위한 프롬프트 견본입니다.
> `[대괄호]` 부분을 실제 값(저장소 경로·파일명·확정된 IA)으로 바꿔 사용합니다.
> 버전 표기 없이 관리하며, 실제 작업 결과가 나오면 이 문서의 프롬프트를 그대로 갱신합니다.

---

## 0. 왜 프롬프트를 둘로 나누는가

Claude Code(CC)와 Codex는 성격이 다릅니다. 같은 프롬프트를 주면 둘 다 결과가 나빠집니다.

| 구분 | Claude Code | Codex |
|---|---|---|
| 강점 | 저장소 전체 맥락 · 다중 파일 · 조사 · 명령 실행 | 명확히 정의된 단일 작업의 빠른 구현 |
| 프롬프트 방식 | 목표·제약 중심, 탐색 여지를 남김 | 파일 경로·입출력·완료 조건을 못 박음 |
| 맡길 일 | Phase 0 조사 · IA 구조 변경 · 라우팅 | 4탭 네비·수익 카드·컴포넌트 단위 구현 |

**핵심은 순서입니다.** CC가 먼저 코드베이스를 조사해 `IMPLEMENTATION_PLAN.md`를 만든 뒤, 확정된 파일 경로로 Codex에 넘깁니다. 계획 없이 Codex에 주면 경로를 추정해 엉뚱한 파일을 고칩니다.

```
CC (Phase 0 조사) → IMPLEMENTATION_PLAN.md (확정 경로) → Codex (컴포넌트 구현)
```

---

## 1. 공통 절대 원칙 (두 에이전트 모두)

1. 기존 API·DB·인증·결제 기능을 **먼저 조사하고**, 새로 만들지 않는다.
2. 데이터 근거가 없는 기능은 구현하지 말고 `TODO`로 표시한다.
3. 시니어 사용성 최우선 — 한글 명확한 메뉴, 본문 최소 17px, 터치 영역 최소 48px, 짧은 문장.
4. 기존 SEO 색인 URL을 함부로 바꾸지 않는다. 변경 시 301·캐노니컬·사이트맵 영향을 점검한다.
5. 결제·상담·신청은 **실제 완료 이벤트까지** 추적한다.
6. 작은 커밋 단위로 진행하고, 변경 파일·이유·검증 결과를 보고한다.
7. 추측을 사실로 쓰지 않는다. 막히면 우회하지 말고 보고한다.

## 2. Claude Code 프롬프트

### 2-1. Phase 0 — 코드베이스 조사

```
당신은 시놀 앱·웹의 Senior Product Engineer이다.
이 저장소를 조사해 4대 메뉴 개편의 실행 계획을 세우는 것이 목표다.
아직 코드를 바꾸지 말고, 조사와 계획만 한다.

## 조사 항목
1. 하단 네비게이션 구현 위치 — 현재 [모임/라운지/+/채팅/마이] 5탭이
   어느 파일에서 정의되는가. 라우팅 구조를 파악한다.
2. 홈 화면 섹션 — 9개 섹션이 서버 응답으로 내려오는가, 하드코딩인가.
   순서·노출을 배포 없이 바꿀 수 있는 구조인가.
3. 채팅 — 모임/1:1 대화 2탭의 컴포넌트와 API. 안 읽음 카운트를
   서버가 내려주는가, 클라이언트가 계산하는가.
4. 수익 카드 — 단체미팅·인연진단·여행 카드가 콘텐츠 카드와
   같은 컴포넌트를 쓰는가.
5. 회원 계정 — 웹·시놀앱·시럽앱이 같은 user 체계인가.
6. 결제 — PG사와 빌링키(정기결제) 발급 가능 여부.
7. 측정 — GA4/GTM/Firebase 설치 현황.

## 절대 원칙
- 코드 변경 금지. 조사와 계획만.
- 프로덕션 변경·개인정보 조회 금지.
- 근거 파일 경로를 항목마다 명시.
- 신뢰도를 확정/유력/추정/미확인 4단계로 표기.

## 출력
docs/IMPLEMENTATION_PLAN.md 로 저장한다:
- 서비스별 스택 확정표
- 4대 메뉴 IA 변경에 손대야 할 파일 목록 (경로 명시)
- 채팅 라우팅 변경 대상 파일
- Codex에 넘길 컴포넌트 작업 목록 (각각 파일 경로·입출력)
- 구현 제약 — 요구사항 재설계가 필요한 항목
- 미확인 항목과 확인 방법
```

```

- primary_nav_tap / mypage_open / chat_entry 이벤트 부착
- 실기기 확인 (Android · iOS)

## 제약
- 기존 채팅 컴포넌트·API 재사용. 새로 만들지 않는다.
- 홈 섹션 규격(radius 16px, 검색어 수집, 정원 표시 등)은 기존 설계 유지.

## 3. Codex 프롬프트

CC가 만든 `IMPLEMENTATION_PLAN.md`에서 확정된 파일 경로를 `[대괄호]`에 넣어 사용합니다.

### 3-1. 4탭 네비게이션 컴포넌트

```
파일: [IMPLEMENTATION_PLAN.md에서 확인된 네비 컴포넌트 경로]
작업: 하단 네비게이션을 4탭으로 교체

입력: 현재 탭 상태 (home/travel/meet/groups)
출력: 4개 탭 렌더 + 선택 탭 표시

요구사항:
- 탭: 홈 / 여행 / 만남 / 모임 (한글 라벨 필수)
- 각 탭 아이콘 + 한글 라벨 병기
- 터치 영역 최소 48px
- 선택·미선택 라벨 크기 동일, 굵기와 인디케이터로만 구분
- 탭 클릭 시 primary_nav_tap 이벤트 (파라미터: menu)

제약:
- 기존 라우팅 인터페이스 유지
- 채팅 탭을 넣지 않는다 (맥락 진입으로 이동됨)

완료 조건:
- [ ] 4탭 렌더·전환 동작
- [ ] primary_nav_tap 발생 확인
- [ ] 실기기 터치 영역 48px 확인
```

### 3-2. 수익 카드 컴포넌트 (콘텐츠와 동일 위계)

```
파일: [수익 카드 컴포넌트 경로]
작업: 단체미팅·인연진단·여행 카드를 콘텐츠 카드와 동일 컴포넌트로 렌더

입력: card_type, 표시 데이터(일정/가격/잔여석 등)
출력: 콘텐츠 카드와 시각적으로 구분되지 않는 카드

요구사항:
- 콘텐츠 카드와 같은 컴포넌트·같은 스타일 사용
- 별도 테두리색·배경색·「광고」 표기 금지
- 단체미팅: 잔여 3석 이하일 때만 강조
- 여행: 정가와 멤버십가 나란히, 실제 상품 가격 연동 (하드코딩 금지)
- revenue_card_impression / revenue_card_tap 이벤트

제약:
- 3종을 연속 배치하지 않는다 (배치는 홈 레이아웃에서 제어)
- 가격은 API 연동. 하드코딩 시 불일치 민원 발생

완료 조건:
- [ ] 콘텐츠 카드와 동일 렌더
- [ ] 잔여석 강조 조건 동작
- [ ] 이벤트 발생 확인
```

### 3-3. 만남 메뉴 — 목적 선택

## 5-2. CC 프롬프트 — 검색·발견 채널 최적화 (SEO/ASO/AEO/GEO)

IA 개편과 **병행**하는 그로스 작업입니다. 실행 대상은 프로토타입이 아니라 **실서비스(sinor.co.kr·스토어)**입니다.
근거는 「시놀 SEO·ASO·AEO·GEO 진단(2026-08-06)」입니다 — 실측 등급: SEO 주의 · ASO 위험 · **AEO 양호** · GEO 주의 · UX 위험.

> **작업 순서** — 진단이 정한 우선순위 6개를 위에서부터. 효과 대비 소요가 짧은 것이 위에 옵니다.

```
당신은 시놀 실서비스의 검색·발견 채널을 최적화하는 그로스 엔지니어다.
근거 문서: 시놀 SEO·ASO·AEO·GEO 진단(2026-08-06, 실측). 아래 우선순위대로 실행하되,
각 변경이 기존 색인·유입을 깨지 않는지 먼저 확인한다. 추측을 사실로 쓰지 않는다.

## 우선순위 1 — ASO · App Store 한국어 등록 (소요 1일)
App Store가 '영어(EN)'로만 등록돼 한국어 키워드가 인덱싱되지 않는다.
- 한국어 로컬라이제이션 추가: 이름·부제·키워드필드(100자)를 한국어로.
- 시놀 부제엔 '5060'을 넣는다(현재 '50+'만 있음). '중장년·5060·모임·단체미팅' 배분.
근거: 한국 전용 서비스인데 iOS 한국어 검색 노출을 통째로 잃고 있음.

## 우선순위 2 — UX · 결제 기본값 카드 전환 (소요 반나절)
기본 결제수단이 무통장 입금이고 '7일 이내 입금' 조건이 붙어 결제 완료율을 깎는다.
- 기본값을 카드로, 무통장은 보조 수단으로 내린다.
- 카드·무통장 모두 '결제 완료' 지점에 purchase 이벤트를 발생시킨다(정기결제 전제조건).
근거: 장기 purchase 20건·구매자 16명 — 월 3,600만 규모 대비 극소수만 잡힘.
