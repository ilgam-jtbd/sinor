# 시놀 백오피스(운영 관리자) 설계서 v1.0

> **목적** — 콘텐츠·이벤트·상품을 **개발 배포 없이** 운영자가 직접 바꾸는 관리 도구를 정의합니다.
> **근거** — 개발 요구서 `docs/05` §4 「어드민 관리 대상 8종」의 운영화. 이번 세션의 확정 사항(이벤트 2종·매출 우선·역컴파일 스택) 반영.
> 작성 Claude Code · 2026-08-09 · 대외비 · 확인란: 신진영 COO · 김민지 대표

---

## 0. 왜 필요한가 · 기존 관리자 현황

**핵심 원칙** — 개발 배포 없이 바꿀 수 있는 범위가 곧 그로스 실험의 속도입니다. 운영 변경마다 개발 배포가 필요하면 개선 주기가 스프린트 단위로 늘어나 실험이 사실상 불가능해집니다.

**기존 관리자 화면 추적 결과** 【확정】
- 자사 앱(시놀 `com.sinor.gathering` · 시럽 `com.sinor_app_front`) APK 역컴파일에서 **시놀 전용 관리자 화면은 발견되지 않음.** 검출된 admin 문자열은 전부 SDK 소속입니다 — Easemob 그룹 방장(`GROUP_ADD_ADMIN`·`USER_MUTED_BY_ADMIN`), Firebase/AppLovin MAX, MySQL 드라이버.
- 웹은 아임웹(Imweb, 유력)으로 **페이지 편집형 CMS만** 있어, 홈 섹션 순서·수익 카드 노출·이벤트 예산 같은 **동적 제어는 불가**.
- 결론: **신규 백오피스 설계**가 맞습니다. 이 문서는 처음부터(from scratch) 설계본이며, "기존 화면 업데이트"가 아니라 "부재 확인 후 신설"입니다.

---

## 1. 설계 원칙

1. **운영자가 배포 없이 바꾸는 범위 = 이 도구의 완료 조건.** §4의 8종은 전부 어드민에서 수정 가능해야 합니다.
2. **미리보기 필수.** 저장 전 실제 화면과 동일한 미리보기를 제공합니다. 시니어 화면에서 잘린 문구·빈 이미지는 오류로 읽힙니다.
3. **가격은 상품 DB 연동.** 하드코딩 금지 — 불일치 민원의 직접 원인입니다.
4. **측정은 콘텐츠와 한 몸.** 항목을 만들면 노출·탭·전환 이벤트가 자동 부착됩니다. "나중에 붙임" 금지.
5. **권한 분리.** 콘텐츠 운영·이벤트(예산)·상품(가격)·측정은 역할이 다릅니다.
6. **수치는 정합기준 정본(`docs/03`) 단일 출처.** 백오피스 입력값도 정본과 어긋나면 경고합니다.

## 2. IA — 메뉴 구조

```
① 대시보드      오늘의 매출·설치·이벤트 성과 요약 + 처리 대기
② 콘텐츠 관리    홈 섹션 순서 · 기획전 배너 · 수익 카드 3종 · 카테고리 · 칼럼 하단 카드 · 빈 상태 문구
③ 이벤트 관리    친구초대 5,000원 · 모임개설 11만P — 예산·기간·어뷰징·성과
④ 상품·가격      단체미팅 일정 · 시럽인연 상담/패키지 · 시놀트립 멤버십
⑤ 커뮤니티       모임 · 스토리(후기/칼럼) · 대화 운영공지·자동초대
⑥ 측정·그로스    이벤트 부착 현황 · 전환추적 연결 · 검색어 로그
⑦ 설정           회원 권한(RBAC) · 노출 규칙 · 웹뷰 맥락 · 앱 유도 규칙
```

개인정보(회원 상세)는 이 도구에서 **조회·다운로드하지 않습니다.** 통계·집계만 봅니다.

## 3. 화면별 상세 (§4 8종 + 확정 추가분)

### 3-1. 콘텐츠 관리

| # | 대상 | 운영자 조작 | 제약 | 이벤트 |
|---|---|---|---|---|
| 1 | 기획전 배너 | 이미지·링크·노출 기간·순서·활성화 | 세션당 첫 노출 | impression·tap |
| 2 | 홈 섹션 순서 | **드래그로 순서 변경** · 섹션 on/off | 규격(radius 16px) 유지 | section_impression·tap |
| 3 | 수익 카드 3종 | 문구·목적지·노출 여부·노출 빈도 상한 | **3종 연속 배치 금지**(자동 검증) | impression·tap·conversion |
| 4 | 카테고리 아이콘 | 라벨·순서·노출 | 6개 이하면 가로 스크롤 | tap |
| 5 | 칼럼 하단 카드 | **주제별 매핑 6종**·문구·목적지 | 건강→모임/재혼→시럽인연/여행→시놀트립 | impression·install_conversion |
| 8 | 빈 상태 문구 | 문구·버튼 목적지 | 본문 17px | impression·cta_tap |

### 3-2. 이벤트 관리 (이번 확정분)

| 이벤트 | 운영자 조작 | 어뷰징 방지 | 성과 |
|---|---|---|---|
| 친구초대 5,000원 | 금액·문구·노출 위치·상시/기간 | **초대 1인당 지급 상한 · 중복 계정 차단 · 초대 코드 마스킹** | 초대 발송·가입·지급 건수·CAC |
| 모임개설 11만P | 포인트·지급 조건·노출 | 개설 후 최소 활동 조건 · 1인 다중 개설 상한 | 개설 수·활성 모임 전환율 |

> **예산 한도·어뷰징 정책은 경영 결정 대상**입니다(현재 대기). 백오피스는 그 값을 **입력·집행·모니터링**하는 자리이며, 정책 자체를 문서에 임의로 확정하지 않습니다.

### 3-3. 상품·가격 (매출 직결 — 하드코딩 금지)

| 상품 | 관리 항목 |
|---|---|
| 단체미팅 | 일정·지역·정원·잔여석·**가격 등급**(99,000~) · 본인인증 옵션 · 신청 완료 회원 자동 초대 |
| 시럽인연 | 상담 슬롯·패키지(가입비, **성혼비 없음** 고정)·총액 비교표 값·매니저 배정 |
| 시놀트립 | 멤버십가(연 49,900)·상품별 정가/멤버십가·동행 매칭·일정 대화방 |

### 3-4. 커뮤니티·대화 운영

- 모임 카테고리·인기·새 모임 노출 규칙
- 스토리(후기/칼럼) 큐레이션·상단 고정
- 대화 **운영 공지 발송·고정(pin)**, 여행·미팅 방 **결제 완료 회원 자동 초대**
- 안 읽음 표시 규칙(탭=점, 목록=숫자)은 앱 규격 유지

## 5. 권한(RBAC)

| 역할 | 범위 |
|---|---|
| 콘텐츠 운영자 | 콘텐츠·커뮤니티·스토리 |
| 이벤트 운영자 | 이벤트 예산·집행 (경영 승인 한도 내) |
| 상품 운영자 | 단체미팅 일정·시놀트립 가격·시럽인연 슬롯 |
| 매니저 | 시럽인연 매칭·상담 배정 |
| 관리자 | 전체 + 권한 부여 + 측정 설정 |

## 6. 측정·그로스 연동

- 항목 생성 시 노출·탭·전환 이벤트 **자동 부착** (수동 X)
- GA4·GTM·서치콘솔·네이버 전환추적 연결 상태를 대시보드에 표시
- `purchase`는 **TossPayments · Play Billing 두 경로 모두** 집계
- 내부 검색어(search_term)·결과 0건 로그 조회

## 7. 운영 가드레일

| 항목 | 규칙 |
|---|---|
| 저장 전 미리보기 | 실제 화면과 동일 미리보기 없이는 발행 불가 |
| 이미지 누락 | 카테고리별 기본 이미지 자동 대체 |
| 가격 불일치 | 상품 DB와 다르면 저장 차단 |
| 수익 카드 | 3종 연속 배치 자동 검증 |
| 앱 유도 규칙 | 시럽인연 상담·여행 결제 페이지엔 앱 유도 삽입 불가(자동 차단) |
| 웹뷰 맥락 | 인앱(web.sinor.co.kr) 노출 시 설치 유도 요소 자동 숨김 |
| 문구 길이 | 초과 시 말줄임이 아니라 입력 단계 경고 |
| 변경 이력 | 누가·언제·무엇을 바꿨는지 로그 |

## 8. 개발 범위 · 미결

- **플랫폼 결정 필요** — 아임웹 head 삽입으로 커버 가능한 범위 vs 별도 백오피스 신규 구축. (D1 회신 연동)
- **회원 계정 통합** — 웹·시놀앱·시럽앱 user 체계 동일 여부(D2)가 자동 초대·설치 기여의 전제
- **이벤트 예산·어뷰징 정책** — 경영 결정 대기
- **개인정보 경계** — 회원 상세는 이 도구에서 조회하지 않음(집계만). 개인정보 처리 방침·접근 통제 별도 확인
