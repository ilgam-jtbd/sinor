## 0. 운영 원칙 (이번 지시 반영) — 사람은 제안만, 나머지는 자동

- **관리 주체는 둘** — 최지영(PO): 우선순위·일정·담당 배정 / 우종선(개발): 이슈·배포·릴리즈.
- **컨펌은 「제안(신규 기획)」만.** 반복 운영(슬랙·CS·백오피스 유입 처리, 상태 갱신, 알림)은 에이전트가 바로 처리하고 보드에 1건 기록. 사람 승인은 **새 기능·예산·가격·제재·개인정보**에만.
- **유입 → 처리 → 기록**이 기본 루프. 제목 접두어 `[슬랙]` `[백오피스]` `[CS]` `[에이전트]`로 유입별 조회.

| 3 | 탭 이동(스케줄·프로젝트·이슈·배포·팀·개요·이력·릴리즈) | 동작. 「팀」은 셀렉터 중복일 뿐 실제 동작 정상 |

| 8 | 시크릿·키·개인정보 | **없음** — API키는 `YOUR_*` placeholder, 이메일은 역할@sinor.co.kr placeholder |
| 9 | firebase_rules 미인증 read/write | **차단됨** — 모든 노드 `auth != null` 요구, 쓰기 상위노드는 userPermissions 검사 |

**발견사항(고치지 않고 보고만)**
1. **P01 프로젝트 이름이 옛 메뉴** — "4대 메뉴 개편 — 홈·여행·만남·모임". 최신 IA는 **홈·모임·여가·만남**(docs/11). 보드에서 이름만 수정 권장.
2. **AF_ 접두어 상수 13개 잔존** — `AF_DB_PREFIX`·`AF_ENV`·`AF_Schedule_`. 원 템플릿 내부 네임스페이스로 화면에 안 보이고 무해하나, "내부 접두어 0건" 표현과는 불일치.
3. **슬랙 가이드에 CSO 역할 표기 2건** — 김연재(CSO) 제거 후 문서에 role 라벨만 잔존. 경영 일정 권한 문구 검토.
4. **admin1234 기본 게이트 비번** — placeholder 유지(정상). **Firebase 연결 전 반드시 변경.** 공개 저장소라 현재 코드가 누구나 열람 가능.

**공개 노출 주의** — 저장소가 public이라 보드에 담긴 **팀명·프로젝트 일정·배포일**이 인터넷에 공개·색인됩니다. 샘플 단계라 당장 문제는 없으나, 실데이터(Firebase) 연결 후에는 **① 게이트 비번 변경 ② 접근 제어**가 필요합니다. 장기적으로 팀명을 역할로 가리거나 비공개 호스팅을 권합니다.

관리 포인트(최지영):
1) 프로젝트 8건 우선순위·배포일·담당 배정 — 스케줄/프로젝트 탭에서 드래그·수정

운영 원칙: 반복 처리는 자동, 최지영 님 컨펌은 「새 기획 제안」에만. 나머지는 보드에 기록만 남습니다.

참고: P01 이름이 옛 메뉴(홈·여행·만남·모임)로 되어 있어요. 최신은 홈·모임·여가·만남입니다 — 보드에서 이름만 바꾸면 됩니다.

## 3. 우종선(개발)에게 — 붙여넣기용

```
우종선 님, 운영보드 검증·배포했습니다. 설정 4가지만 하시면 팀 공유가 켜집니다.
· 보드: https://ilgam-jtbd.github.io/sinor/board/
· 설정 가이드: 보드 폴더 README_시놀_설정가이드.md (15분)

개발 설정(우종선):
1) Firebase RTDB + 구글 로그인 — index.html의 firebaseConfig( YOUR_* 자리 )에 콘솔 값 입력
2) 보안 규칙 — firebase_rules.json 그대로 임포트(이미 인증 게이트, 미인증 read/write 차단)
3) 관리자 게이트 비번 admin1234 → 실제 값으로 변경 (공개 저장소라 필수)
4) QA 첨부 = Cloudinary 연동 — 설정에서 cloudName + unsigned uploadPreset 한 줄 입력
   (키·시크릿은 커밋 금지. 클라우디너리는 unsigned preset이면 서버 시크릿 불필요)

검증 결과: 인라인 문법 OK · 이슈 시드 유효 · 담당 id 미아 0 · 서비스 8종(어드민 2종) ·
보안 규칙 안전 · 실제 키/개인정보 없음. 치명 오류 0.

주의: 저장소 public이라 팀명·로드맵 공개 노출됩니다. Firebase 연결 후 접근 제어 검토 부탁드립니다.
```
