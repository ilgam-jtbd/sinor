# 코워크 배포 프롬프트 — 프로토타입 GitHub Pages 공개

> **용도** — `prototype/index.html`을 GitHub Pages로 공개해 디자이너·개발자·이해관계자가 링크로 열어보게 합니다.
> 참조 예시(banns0104.github.io/velor-seo 등)와 같은 정적 페이지 배포 방식입니다.
> 이 저장소에 push 권한이 있는 세션(Claude Code)이 실행하거나, 사람이 GitHub 웹에서 직접 설정합니다.

---

## 0. 현재 상태

- 프로토타입 파일: `prototype/index.html` — 이 저장소 브랜치 `claude/learning-session-b0yeka`에 커밋됨 (CC가 push 완료)
- 빌드 불필요 · 외부 의존 없음 — 그대로 호스팅 가능

## 1. 사람이 GitHub 웹에서 (가장 빠름, 5분)

1. `github.com/ilgam-jtbd/sinor` → **Settings → Pages**
2. **Source**: Deploy from a branch
3. **Branch**: `main` 선택 · 폴더 `/ (root)` → **Save**
   - (아직 `main`에 병합 전이면 아래 2번 방법으로 브랜치 병합 먼저)
4. 1~2분 후 접속: **`https://ilgam-jtbd.github.io/sinor/prototype/`**
5. 이 링크를 디자이너·개발자·대표님께 공유

> Pages가 `main`만 배포한다면, `claude/learning-session-b0yeka`를 `main`으로 PR 병합한 뒤 위 설정을 합니다.

## 2. Claude Code(CC) 세션에 시킬 때 — 프롬프트

```
이 저장소의 prototype/index.html 을 GitHub Pages로 공개하려 한다.

## 작업
1. 현재 브랜치(claude/learning-session-b0yeka)를 main으로 병합하는 PR을 만든다.
   (또는 기존 열린 PR이 있으면 그것을 쓴다)

   사람이 Settings→Pages에서 해야 할 단계를 정확히 알려준다.
3. 배포 URL이 확정되면 prototype/README.md 와 docs/08 인수인계 문서에

## 제약
- 프로덕션(실서비스)에 영향 주지 않는다. 이 저장소는 분석·프로토타입 전용이다.
- 대외비 원본(pptx·docx·pdf)은 커밋하지 않는다.
- 프로토타입의 색·문구는 초안이므로 임의로 바꾸지 않는다.

## 완료 보고
- PR 링크 · Pages 배포 URL · 반영한 파일 목록
```

## 3. 커스텀 도메인(선택)

`prototype.sinor.co.kr` 같은 서브도메인으로 붙이려면:
- GitHub Pages → Custom domain에 도메인 입력
- DNS에 CNAME 레코드(`prototype` → `ilgam-jtbd.github.io`) 추가
- **주의** — 실서비스 `sinor.co.kr` 본 도메인/색인에 영향 없게 서브도메인만 사용

## 4. 공유 시 함께 전달할 안내

프로토타입 링크를 보낼 때 아래를 함께 적으면 오해가 없습니다.

> - 상단 **앱/웹 토글**과 하단 **4대 메뉴**를 눌러 화면을 이동해 보세요
> - **색·아이콘·최종 카피는 디자인 단계에서 확정**하는 초안입니다 — 지금은 구조·콘텐츠 배치 합의가 목적
> - 실제 모임명·후기는 대표 예시이며, 실데이터 연동은 개발 단계에서
