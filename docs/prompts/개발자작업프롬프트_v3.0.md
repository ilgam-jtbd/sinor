## 0. 작업 순서와 도구 분담

| 구분 | Claude Code | Codex |
|---|---|---|
| 강점 | 저장소 전체 맥락 · 다중 파일 · 조사 | 정의된 단일 작업의 빠른 구현 |
| 지시 방식 | 목표·제약 중심, 탐색 여지를 남김 | 파일 경로·입출력·완료 조건을 명시 |
| 맡기는 일 | 코드베이스 조사 · IA 구조 변경 · 라우팅 · 채널 최적화 | 4탭 네비 · 수익 카드 · 만남 목적 선택 · 대화방 컴포넌트 |

**순서가 중요합니다.**

```
Claude Code (조사·계획) → 실행 계획서 (확정 경로) → Codex (컴포넌트 구현) → Claude Code (통합·이벤트 부착)
```

계획 없이 Codex에 주면 경로를 추정해 다른 파일을 고칩니다.

## 1. 이미 확정된 것 — 다시 조사하지 않습니다

자사 앱 기술 실사(APK 역컴파일)로 확인된 구성입니다. Phase 0에서 **조사 대상에서 제외**합니다.

| 항목 | 시놀 `com.sinor.gathering` | 시럽 `com.sinor_app_front` |
|---|---|---|
| 프레임워크 | Flutter(Dart AOT) + Kotlin | 동일 |
| SDK | minSdk 24 / target 36 | 동일 |
| 채팅 | Easemob | Easemob |
| 결제 | TossPayments (웹결제) | TossPayments + Play Billing v8 |
| 인증·미디어 | Facebook 로그인 | Agora RTC · ML Kit Face |
| 광고 | AppLovin · Pangle · Adrop · AdMob | — |
| 공통 | Firebase(FCM·Crashlytics·RemoteConfig, `sinor-8b864`) · S3(서울)+CloudFront · Adrop 스플래시 런처 | |

비즈니스 로직은 Dart AOT로 컴파일되어 **소스 복원이 불가능**합니다. 스택·SDK·권한·엔드포인트만 확정 범위입니다.

## 2. 공통 원칙

1. 기존 API·DB·인증·결제 기능을 먼저 확인하고 새로 만들지 않습니다
2. 시니어 사용성 최우선 — 한글 명확한 메뉴, 본문 최소 17px, 터치 영역 최소 48px
3. 기존 색인 URL을 변경하지 않습니다. 불가피하면 301과 캐노니컬을 함께 적용합니다
4. 결제·상담·신청은 실제 완료 이벤트까지 부착합니다
5. 작은 커밋 단위로 진행하고 변경 파일·이유·검증 결과를 보고합니다
6. 확인된 사실과 추정을 구분해 기록합니다

### 2-1. 역공학 · 바이너리 분석 규칙 (확인: 신진영 COO · 김민지 대표)

```
1. 실서비스 그로스 작업(SEO/ASO/AEO/GEO)은 공개 스토어·웹 콘텐츠만 사용한다.
2. 자사 앱(시놀 com.sinor.gathering · 시럽 com.sinor_app_front)의
   APK 역컴파일은 기술 실사 트랙에서 허용한다.
   - 대상: 자사가 배포한 자사 자산에 한한다.
   - 목적: 개발 스택·SDK·권한·엔드포인트 확인.
   - 금지: 타사 앱 역공학, 보호 우회, 서버 비밀키 추출·유출.
   - 산출물에 서버 secret key를 기재하지 않는다.
3. 결과는 신뢰도(확정/유력/추정/미확인)를 붙여 남긴다.
```

## 3. Claude Code 지시

### 3-1. Phase 0 — 코드베이스 조사

```

## 이미 확정된 것 — 조사 대상 제외
Flutter(Dart AOT)+Kotlin · Easemob 채팅 · TossPayments · Play Billing v8
Agora RTC · ML Kit Face · Firebase(sinor-8b864) · S3(서울)+CloudFront

## 조사 항목
1. 하단 네비게이션 구현 위치 — 현재 5탭이 정의된 파일과 라우팅 구조

7. 측정 — GA4/GTM/Firebase 설치 현황과 purchase 이벤트 부착 지점
8. 웹뷰 — 앱이 web.sinor.co.kr를 임베드하는 지점과 인앱 감지 방법
```

### 3-2. IA 구조 변경

```

## 작업

- 실기기 확인 (Android · iOS)

- 기존 Easemob 채팅 컴포넌트·API 재사용. 새로 만들지 않는다.
```

실행 계획서에서 확정된 파일 경로를 `[대괄호]`에 넣어 사용합니다.

### 4-1. 4탭 네비게이션

```
파일: [실행 계획서에서 확인된 네비 컴포넌트 경로]
작업: 하단 네비게이션을 4탭으로 교체

요구사항:
- 탭: 홈 / 여행 / 만남 / 모임 (한글 라벨 필수)

- 선택·미선택 라벨 크기 동일, 굵기와 인디케이터로만 구분

제약: 기존 라우팅 인터페이스 유지. 대화 탭을 넣지 않는다.

완료 조건:
[ ] 4탭 렌더·전환 동작
```

### 4-2. 수익 카드 (콘텐츠와 동일 위계)

```
파일: [수익 카드 컴포넌트 경로]
작업: 단체미팅·인연진단·여행 카드를 콘텐츠 카드와 동일 컴포넌트로 렌더

요구사항:
- 콘텐츠 카드와 같은 컴포넌트·같은 스타일 사용
- 별도 테두리색·배경색·「광고」 표기 금지
- 단체미팅: 잔여 3석 이하일 때만 강조
- 여행: 정가와 멤버십가 병기, 실제 상품 가격 연동 (하드코딩 금지)
- revenue_card_impression / revenue_card_tap 이벤트

제약: 3종을 연속 배치하지 않는다 (배치는 홈 레이아웃에서 제어)
```

### 4-3. 만남 — 3분기 + 공감 배지

```
파일: [만남 메뉴 화면 경로]
작업: 만남을 3분기로 구성하고 공감 배지를 붙인다

요구사항:
- 1:1(시럽) → 시럽 앱, 성인 등급 18+ 안내 병기

- 공감 배지 3종(재혼 이해·자녀 이해·사별 공감)
  · 본인이 스스로 선택해 다는 신호. 시스템이 자동 부여하지 않는다.
  · 선택형이며 달지 않은 회원에게 불이익이 없어야 한다.
  · 배치: 프로필 · 모임 참가자 목록 · 단체미팅 신청 · 인연 진단 결과
```

| `mypage_open` | entry_point | 마이페이지 진입 |

| `empathy_badge_set` | badge_type | 공감 배지 설정 |
