## 3. 추가 확인 요청 — 브라우저·콘솔로 실물 확인 (⭐ 이번 핵심 추가분)

### 3-①. 측정 공백 — 서치콘솔·서치어드바이저 연결 상태 **재확인**
> 정본 §4는 둘 다 **미연결(추정)** 로 적혀 있습니다. **실제 콘솔에 들어가 연결 여부를 확정**해 주십시오. (개인정보·회원 데이터는 조회하지 말고, 연결/설정 상태만 확인)

| 확인 항목 | 어디서 | 확정할 것 |
|---|---|---|
| **구글 서치콘솔** 연결 | search.google.com/search-console | sinor.co.kr 속성 등록 여부 · 소유확인 메타/DNS · 사이트맵 제출 여부 |
| **네이버 서치어드바이저** 연결 | searchadvisor.naver.com | 사이트 등록·소유확인 · 사이트맵/robots 제출 여부 |
| robots.txt / sitemap.xml | `sinor.co.kr/robots.txt` · `/sitemap.xml` 직접 접속 | 크롤링 허용 여부 · **AI 크롤러(GPTBot·PerplexityBot·ClaudeBot·Google-Extended) 차단 여부** · 사이트맵 존재·갱신일 |
| GA4 search_term 수집 | GA4 관리 | 앱·웹 내 검색 4,232명의 검색어가 수집되는지 (정본 §4 미확인 항목) |

**왜 중요한가** — 서치콘솔·서치어드바이저가 없으면 *어떤 검색어로 들어오는지 데이터가 없어* SEO 개선의 판정 자체가 불가합니다(정본 §4). GEO도 "AI 크롤러가 sinor.co.kr을 못 읽으면 인용 안 됨"이라 robots 확인이 GEO 0단계입니다.

### 3-②. 기존 시놀 **아임웹(Imweb) API·페이지** 확인
> 정본 §7은 시놀 웹 플랫폼을 **아임웹 유력**(칼럼 URL `?bmode=view&idx=`·`doz_` 접두)으로 봅니다. 사실이면 `<head>` 코드 삽입·페이지별 메타·GTM 설치가 **가능**해 SEO 실행의 최악 시나리오를 피합니다. **이 가정을 확정**해 주십시오.

| 확인 항목 | 어디서 | 확정할 것 |
|---|---|---|
| 플랫폼이 아임웹인가 | 아임웹 관리자 로그인 | 아임웹 여부 확정 (유력 → 확정 승격) |
| **아임웹 SEO 설정** | 관리자 `admin/config/seo` | 사이트 제목·설명·OG 태그·소유확인 메타 지정 가능 범위 |
| **페이지별 메타·`<head>` 코드 삽입** | 관리자 | 페이지 단위 title/description 지정 가능 여부 · `<head>` 스크립트(JSON-LD·GTM) 삽입 가능 여부 |
| **아임웹 API** | 관리자에서 API 키 발급 | 페이지·메뉴 목록을 받아 **타깃 경로(web:…)가 실제 존재하는 페이지인지 대사**할 수 있는지 (키워드관리 요구서 v1.0 §8) |
| 서브도메인 `web.sinor.co.kr` | 직접 접속 | 용도·색인 상태 (중복 색인이면 SEO 손실 — 정본 §7·§10 미확인) |

**보안 주의** — API 키·관리자 비밀번호는 **문서·코드 어디에도 기재 금지**. 확인이 끝나면 채팅으로 공유된 관리자 비번은 변경 권장. 회원 데이터는 조회하지 말고 **구조·설정만** 확인.

**왜 중요한가** — 아임웹이 확정되고 `<head>` 삽입이 가능하면 → 로드맵 **1단계(title 재작성·시맨틱)·2단계(FAQPage·Product+Offer 스키마)·측정(GTM·GA4 이벤트)** 가 전부 실행 가능해집니다. 불가하면 대안(플랫폼 이전 등)을 Cowork가 판단해야 하므로, **실행 착수 전 반드시 확정**이 필요합니다.

### 3-③. 발행 요청 — YouTube 콘텐츠 + 웹·앱 링크 집약 (로드맵 3단계 실행) ⭐
> 로드맵 **3단계(브랜드 언급)** 의 첫 실행분입니다. 트렌드 결론 3 — *백링크보다 브랜드 언급, YouTube 언급 상관 **0.74*** — 을 시놀에 적용합니다.

**작업 순서 (주제 부합 → 신뢰 → 링크 → 발행)**
1. **주제 부합(topical relevance) YouTube 콘텐츠 제작** — 시놀의 실제 주제(5060 만남·모임·오늘의운세·재혼/시럽인연·시놀트립)에 맞는 영상. 아무 주제나 올리지 않고, 검색·AI가 "시놀 = 이 주제"로 엮도록 **주제를 좁혀서** 만듭니다. (백링크·신뢰 신호 = 브랜드 엔티티 강화)
2. **영상 상세페이지·설명란(그리고 웹 상세페이지)에 아래 링크 세트를 표준 블록으로 삽입** — 웹사이트 + 시놀·시럽 각 Android/iOS 앱 링크를 **항상 같은 형태**로. 이는 `schema.org sameAs`와 같은 **브랜드 엔티티 연결**로, 검색·AI가 웹과 앱을 한 브랜드로 묶게 합니다(ASO v5.1 §8 엔티티 확립과 동일 원리).
3. **발행** 후 유입은 UTM으로 추적.

**설명란/상세페이지 표준 링크 블록** (정본 §6 실측 식별자 기준 — 복사해 사용):

```

▶ 시럽인연(프리미엄 결혼정보) : https://silovematch.sinor.co.kr

[시놀 앱]
· Android : https://play.google.com/store/apps/details?id=com.sinor.gathering

[시럽 앱]
· Android : https://play.google.com/store/apps/details?id=com.sinor_app_front
· iOS : https://apps.apple.com/kr/app/시럽/id6474283649
```

|---|---|---|
| 시놀 웹 | `https://sinor.co.kr` | 확정 |
| 시럽인연 | `https://silovematch.sinor.co.kr` | 확정 |
| 시놀 Android | `com.sinor.gathering` | 확정(정본 §6) |

**지킬 것**
- **CLAUDE.md §6 준수**: 자녀 타깃/시럽인연 상담·여행 결제 지면에는 **앱 유도 대신 공유 버튼**, 시럽 앱 유도는 `/silovematch` 계열에서만 + **만 19세 이상(19+) 안내 병기**(App Store 실물 등급 19+). 영상 설명란은 정보 제공이라 링크 게시 가능하나, **웹 랜딩에 심을 때는 페이지군별 목표 하나** 원칙을 지킵니다.
- **실행 킷 완성** — 링크 표준 블록·UTM 규칙·sameAs JSON-LD·YouTube 주제안 5종은 `docs/prompts/시놀_발행킷_20260827.md`에 정리됨(2026-08-27 Cowork). 하트링크(4번째 앱)는 이번 블록에서 제외.
- **UTM은 외부 유입(영상 설명란)에만** — 내부 페이지 링크에 UTM을 붙이면 canonical이 흔들립니다(SEO 코드 §7 내부링크 원칙과 상충). 예: `?utm_source=youtube&utm_medium=description&utm_campaign=<영상슬러그>`.
- iOS 시럽 링크 **확정 완료**(`app/시럽/id6474283649`) — 발행 가능.

**왜 중요한가** — YouTube는 상관 0.74로 백링크(0.19~0.24)보다 강한 AI 가시성 신호입니다. 주제 부합 영상 + 일관된 웹·앱 링크 블록은 (1) 백링크·(2) 브랜드 언급·(3) 엔티티 연결을 한 번에 만들어, **GEO에서 "시놀 = 5060 만남/운세/재혼"으로 인용되게** 하는 가장 비용 효율 높은 초기 실행입니다.
