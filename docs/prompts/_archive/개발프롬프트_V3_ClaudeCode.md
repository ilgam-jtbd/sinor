# V3 개편 — Claude Code 실행 프롬프트

**언제 쓰나** — 저장소 전체 맥락이 필요한 일: 코드베이스 조사·IA 구조 변경·라우팅 재배치·리팩터링·QA.
CC는 목표와 제약을 주고 탐색 여지를 남길 때 결과가 좋습니다. 단계를 과하게 못 박지 않습니다.

> 원본: `docs/incoming/V3원본_개발프롬프트.md` (Cowork 제공)
> 이 파일은 그 프롬프트를 **CC 강점(조사·구조 변경)에 맞게** 재구성한 것입니다. 컴포넌트 단위 구현은 `개발프롬프트_V3_Codex.md`로 넘깁니다.

---

## 절대 원칙 (CLAUDE.md와 동일)

1. 기존 API/DB/인증/결제를 **먼저 조사하고 새로 만들지 않는다**
2. 데이터 근거 없는 기능은 구현하지 말고 TODO로 표시한다
3. 시니어 사용성 최우선 — 한글 명확한 메뉴, 본문 17px, 터치 48px, 짧은 문장
4. 기존 SEO 색인 URL을 함부로 바꾸지 않는다 (변경 시 301/캐노니컬/사이트맵 점검)
5. 결제·상담·신청은 **실제 완료 이벤트까지** 추적한다
6. 작은 커밋 단위, 변경 파일·이유·검증 결과를 보고한다
7. 요구사항을 임의 확장하지 않는다. 더 나은 방법은 실행하지 말고 제안으로 남긴다

## Phase 0 — 조사 (코드 수정 금지)

```markdown
## 역할
시놀 앱·웹의 Senior Product Engineer. 지금은 조사만 한다. 코드를 수정하지 마라.

## 목표
V3 IA — 하단 메뉴를 홈/여행/만남/모임 4개로 단순화하고 개인 설정을 우측 상단
마이페이지로, 채팅을 맥락형 진입으로 바꾸는 것. 기존 자산을 최대한 재사용한다.

## 근거
docs/07_V3_IA_재정의.md 의 9섹션→4메뉴 매핑. 수치는 docs/03_정합기준_정본_2026-08.md.

## 작업 (조사)
현재 구조를 파일 경로와 함께 표로 정리한다:
1. navigation / routing 컴포넌트 — 하단 5탭이 어디서 정의되는가
2. home composition — 9개 홈 섹션이 각각 어떤 컴포넌트/API에서 오는가
3. chat — 2탭·안읽음 카운트가 서버 응답인가 클라이언트 계산인가
4. mypage — 현재 '마이' 탭의 구성
5. auth / user — 웹·시놀앱·시럽앱이 같은 user 테이블·user_id를 쓰는가
6. API — 모임·대화·상품·결제 엔드포인트 목록
7. analytics — 현재 GA4/이벤트 부착 방식
8. payment — PG·빌링키 지원 여부
9. admin — 배너·섹션 순서·카드를 배포 없이 바꾸는 구조가 있는가

## 산출
IMPLEMENTATION_PLAN.md 작성:
- 위 9개 항목의 현재 구조 표 (항목·파일 경로·재사용 가능 여부·비고)
- 9섹션→4메뉴 재배치 시 재사용/신규/수정 분류
- 신뢰도 표기 (확정/유력/추정/미확인), 미확인은 확인 방법
계획 승인 전에는 코드를 수정하지 마라.
```

## Phase 1 — 안전한 IA (승인 후)

```markdown
IMPLEMENTATION_PLAN.md 기준 Phase 1만 구현한다. 새 API를 만들지 말고 기존
route/component를 재사용한다.
- 하단 navigation을 홈/여행/만남/모임 4개로 변경
- 마이페이지를 우측 상단으로 이동 ('마이' 단독 메뉴명 사용 안 함)
- 채팅을 하단에서 제거하고 모임 상세/프로필/헤더에서 진입 가능하게. 기존 대화방·
  2탭·안읽음 규칙은 유지
- 이벤트 추가: primary_nav_tap(menu) · mypage_open · chat_entry(source, room_type)
- 빌드·테스트 실행, 변경 파일과 결과 보고

## 제약
- 승인 없는 DB migration 금지 / 기존 URL 삭제 금지 / 기존 결제 로직 대체 금지
- 확인 안 한 API endpoint 생성 금지 / 디자인만 보고 기능 추정 구현 금지
- 불가능하면 대안 제시하고 멈춘다
```

## Phase 2~4 — 홈 재배치 · 만남/여행 연결 · 웹

- **Phase 2 (홈)**: 9섹션 데이터를 목적형 섹션으로 재배치. 서버 제어 가능한 순서/ON-OFF 구조 확인. 하드코딩 가격 금지
- **Phase 3 (만남/여행)**: 기존 시럽/시럽인연/단체미팅/트립 URL·기능을 연결. 실제 CTA와 이벤트 부착. 시럽인연은 인연진단→상담→전화 최단 경로
- **Phase 4 (웹)**: 기존 URL 보존. 스마트 앱 링크·칼럼 CTA·`/meeting` 연결·SEO/GEO/AEO 메타·스키마 점검
