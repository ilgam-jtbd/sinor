> **robots.txt / GEO (대표님 질문 회신)** — robots.txt는 도메인 루트 파일이라 **호스팅 주체가 있는 곳에서** 설정. 아임웹은 SEO 설정이 제한적 — 커스텀 robots.txt·관리자 경로 제외가 되는지 아임웹 플랜 확인 필요. **모바일웹 통합(자체 호스팅) 시점에 자체 설정**이 정석.

### ① GitHub + Linear 병행 — 【2026-08-09 재검토 필요】

> **재검토 사유** — 확정 당시 저(Claude Code)는 **현장이 이미 Notion을 쓰고 있다는 사실을 모른 채** 안을 올렸습니다. 슬랙 확인 결과 `SN-####` 티켓이 전부 Notion이고, **SinorAS 봇**이 슬랙↔Notion을 잇고 스프린트 현황을 자동 게시합니다(2026-07-07부터 운영 중). 이대로 두면 상태가 **3곳(Notion·GitHub·Linear)으로 갈라집니다** — 이 확정의 원래 목적과 정반대입니다.
>
> | 안 | 내용 | 대가 |
> |---|---|---|
> | **A. Notion 유지 + GitHub 연동** | 상태 원본 = Notion · GitHub은 코드·PR·릴리즈만 · Linear 미도입 | 도는 걸 안 흔듦 · 이 확정을 수정해야 함 |
> | **B. 확정대로 진행** | 상태 원본 = GitHub 이슈 · Notion에서 이관 | 팀이 쓰던 도구·봇을 교체. 이관 비용과 저항 |
> | **C. 경계 분리** | Notion=기획·회의 / GitHub=개발 티켓 | 경계가 흐린 항목에서 다시 갈라짐 |
>
> **Claude Code 권고 = A.** 팀이 이미 쓰고 봇 자동화까지 붙은 도구를 새 문서 하나 때문에 바꾸는 것은 리소스만 큽니다. **결정은 대표·COO 몫**이며, 결정 전까지 아래 원문은 보류 상태로 둡니다.

**원문(2026-08-09 확정 시점)**

두 도구를 모두 씁니다. 다만 **역할을 나누고 상태의 원본을 하나로 고정**합니다.

| 도구 | 역할 |
|---|---|
| **GitHub** | 기록 원본 — 이슈 · PR · 릴리즈. **상태(status)의 단일 출처** |
| **Linear** | 일정 관리 — 사이클 · 담당 배치 · 우선순위 |

에이전트가 GitHub → Linear로 **단방향 반영**합니다. 양방향으로 두면 두 곳의 상태가 갈라지고, 갈라지면 아무도 어느 쪽을 믿어야 할지 모르게 됩니다.

## 4. 되돌리려면 다시 결정이 필요한 것

- **수익 카드 = 콘텐츠 카드와 동일 컴포넌트** — 테두리색·배경색·「광고」 표기 금지

- **릴리즈 발행은 관리자 승인 후에만** — 에이전트 자동 실행(L1) 불가
