## 3. 채팅 — 아고라와 Easemob은 같은 것을 다르게 부른 것입니다 【유력】

**표면상 모순** — 제 역컴파일 보고서는 채팅 엔진을 **Easemob/Hyphenate**(`com.hyphenate.chat`, `libhyphenate.so`)로 적었고, 현장은 **"아고라"**라고 부릅니다(김민지 7/27 "채팅 아고라 → 내부 시스템", 최지영 우선순위 2 "아고라 → 신규 채팅 개발").

**해석** — **Agora Chat SDK가 Easemob(환신) 기술 기반**이라 Android 패키지명이 `com.hyphenate.*`로 남습니다. 즉 두 이름은 같은 엔진을 가리킵니다. 화상·음성의 Agora RTC와는 **다른 제품**입니다.
**확인 방법** — Agora 콘솔에서 Chat 프로젝트 App ID·SDK 버전 확인, 또는 앱 `libagora*.so` / `io.agora.chat` 심볼 대조.

### 3-1. 최지영이 막아둔 질문에 답이 됩니다

최지영(7/27) — "**아고라 사용 시 기존 대화 데이터를 신규 채팅으로 그대로 이관 가능한지 우선 확인 필요.** 이관 불가능 → 오픈 전 데이터 소실 공지 선행 발송 필요"

이 질문이 **우선순위 2번 전체를 막고 있습니다.** Easemob/Agora Chat 계열이면 서버에 메시지 이력이 보관되고 **REST API로 내려받는 경로가 존재**하는 것이 일반적입니다 — 즉 **이관 가능 쪽에 무게가 실립니다** 【추정 — 플랜·보관기간에 따라 달라지므로 반드시 확인】.

**확인 순서(권장)**
1. Agora/Easemob 콘솔에서 **현재 플랜의 메시지 이력 보관 기간** 확인 — 이게 상한입니다
2. History/Export REST API **사용 가능 여부와 호출 한도** 확인
3. 1개 방으로 **시험 추출** → 스키마 확인
4. 그다음에 마이그레이션 일정 확정

**보관 기간이 짧으면 "이관 가능"이어도 오래된 대화는 이미 없습니다.** 공지 발송 여부는 그 결과를 보고 정해야 합니다. 8/7에 김민지가 "채팅방 언제 올라가는지" 다시 묻는 걸 보면 **1주차 항목인 채팅이 지연 중**입니다.

## 5. 어제 확정한 것과 충돌하는 게 하나 있습니다 — 이슈 트래커

**어제 확정** — GitHub + Linear 병행, 상태의 원본은 GitHub 이슈.
**현장 실제** — **Notion**입니다. `SN-####` 티켓이 전부 `app.notion.com`이고, **SinorAS 봇**이 슬랙↔노션을 잇고 스프린트 현황을 자동 게시합니다. 우종선이 7/7에 도입해 이미 운영 중입니다.

**그대로 두면 상태가 3곳(Notion·GitHub·Linear)으로 갈라집니다.** 어제 GitHub+Linear를 정한 이유가 「두 곳이 갈라지는 것을 막기 위해」였는데, 세 번째가 이미 돌아가고 있었습니다.

**선택지와 대가** — 이건 제 판단 영역이 아니라 결정이 필요합니다.

| 안 | 내용 | 대가 |
|---|---|---|
| **A. Notion 유지 + GitHub 연동** | 상태 원본 = Notion. GitHub은 코드·PR·릴리즈만. Linear 도입 안 함 | 이미 도는 걸 안 흔듦 · 어제 확정 ①을 수정해야 함 |
| **B. 어제 확정대로** | 상태 원본 = GitHub 이슈. Notion에서 이관 | 팀이 쓰던 도구·봇을 갈아엎음. 이관 비용과 저항 |
| **C. Notion=기획/회의, GitHub=개발 티켓** | 경계로 나눔 | 경계가 흐린 항목에서 다시 갈라짐 |

**저는 A를 권합니다.** 팀이 이미 쓰고 있고 봇 자동화까지 붙어 있는 도구를 새 문서 하나 때문에 바꾸는 건 「좋은 문제 = 겪는 사람 수 × 고통 ÷ 리소스」 기준에서 리소스만 큽니다. 다만 **결정은 대표·COO 몫**이라 `docs/10`에 재검토 항목으로 올려두었습니다.
