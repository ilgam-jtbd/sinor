PART 4 · 실무 교본

SEO 코드 7계층 — 왜 이렇게 짜는가

크롤러는 head부터 위→아래로 읽고, 위에 있을수록 중요하다고 판단합니다. 각 계층은 서로 다른 독자를 위해 존재합니다. 눌러서 펼쳐 보세요.

1 head 메타 — title·description·canonical 독자 · 구글/네이버 봇
title 맨 앞에 검색어, 브랜드는 뒤로. description 155자 이내. canonical으로 원본 URL 지정.
처방 예시 — 시럽인연: 중장년 결혼정보 시럽인연 | 50·60대 재혼 상담 · 성혼비 없음
흔한 실수 — 브랜드를 앞에 두는 것. 인지도 낮은 초기엔 검색어가 앞입니다.
2 JSON-LD @graph — 구조화 데이터 묶음 독자 · 리치결과 엔진
LocalBusiness + FAQPage + ItemList를 하나의 script에 @graph로 묶습니다. 시럽인연 FAQ는 이미 본문에 있으므로 표시만 붙이면 스니펫 후보가 됩니다.
3 Microdata — Product + Offer 독자 · 상품 크롤러
price는 반드시 Offer 안에. Product 직속에 두면 서치콘솔이 "offers/review/aggregateRating 필요" 에러를 냅니다. 시놀트립·여행 상품에 적용.
4 이미지 alt — 전부 키워드로 시작, 전부 고유 독자 · 이미지 검색 봇
alt는 핵심 키워드로 시작하되 모두 서로 달라야 합니다. 같은 alt 반복은 키워드 스터핑=스팸 판정.
5 HTML 시맨틱 — h1 하나, 위가 중요 독자 · 모든 크롤러
h1은 페이지당 1개. 상품 카드는 <article>. 문서의 위→아래가 중요도 순서라는 전제로 배치합니다.
6 링크·CTA — PageRank 집중 독자 · 구글 + 사용자
내부 링크를 한 URL에 집중합니다. 버튼 앵커텍스트에 키워드를 넣습니다 — "자세히 보기"는 버립니다.
7 OG · Twitter Card — SNS 미리보기 독자 · SNS 크롤러
og:image는 절대 URL 필수(상대경로면 SNS 인식 실패). twitter:card=summary_large_image.
배포 전 체크 14 (요지) — title 검색어 앞 · description 155자 · canonical · JSON-LD 유효 · Product에 Offer · 모든 img에 alt · alt 고유 · og:image 절대 URL · h1 1개 · 모바일 안 잘림 · PageSpeed 모바일 70+ · sitemap · robots 허용. 검증 도구 — 리치결과 테스트 · 서치콘솔 · PageSpeed Insights · Schema Validator · 네이버 웹마스터.

틴더조차 AEO는 30점입니다. AEO(답변엔진)는 업계 전반의 약점이고, 그래서 먼저 채우는 쪽이 유리합니다.

VELOR가 다르게 한 것 — 전부 지금 시놀도 할 수 있는 것들입니다.
  • JSON-LD 스키마 11종 한 번에 — Organization·WebSite·FAQPage·Question·Answer·BreadcrumbList 등을 하나의 @graph로 묶어 넣음(프롬프트 A와 동일한 방식)
  • llms.txt 존재 — 시놀도 이미 있음(위 확인 스탬프 참조) — 이 항목은 이미 동률
  • About(회사소개) 페이지 + Organization 스키마 연결 — 시놀도 /company 페이지는 있음, 스키마 연결만 없음(프롬프트 A로 해소)
  • title·H1·메타설명의 브랜드명 일치 — 셋 다 같은 이름을 씀 (시놀은 title 7자·H1 0개라 애초에 비교가 안 됨 — 프롬프트 B로 해소)
  • 보안 응답 헤더 4종(HSTS·X-Content-Type-Options·X-Frame-Options·CSP) — 점수엔 안 들어가지만 AI·검색엔진이 "신뢰할 만한 사이트인가" 참고 신호로 봄. 아임웹 제약 가능성 있어 개발 확인 필요

즉 VELOR와 시놀의 격차는 특별한 기술이 아니라 위 실행 순서 1~4번을 이미 끝냈는지 여부입니다. 순서대로 하면 같은 점수대에 도달할 수 있습니다.
